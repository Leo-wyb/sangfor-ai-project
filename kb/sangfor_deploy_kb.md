## 一、参照网络分层模型（部署位置坐标系）

附件一全部真实拓扑可归纳为以下分层，每台设备的"部署位置"都落在这些层之间的链路或层内旁挂点上：

```
L0 互联网 / 运营商（多线路：电信/联通/移动/专线/香港线路…）
    │  （多线时先经「接入交换机(分线用)」汇聚各运营商线路）
L1 出口区          光猫 / 出口路由器 / SDW-R / AD(链路负载)
L2 出口安全区      AF(出口防火墙)、WAF、WOC(分支侧)、SSL VPN/aTrust(入口发布)
L3 行为/优化区     AC(网桥串接) —— 附件二标准链路：AD→AF→AC→核心
L4 核心交换机      （双核心堆叠/VRRP；aTrust/STA 常旁挂于此）
L5 汇聚/接入       接入交换机、无线控制器AC、POE交换机、桌面云汇聚(万兆)
L6 终端            PC / 笔记本 / 云终端 / AP / 摄像头 / 打印机 / IPGuard终端
S  服务器区        （常经「数据中心防火墙 AF」或汇聚交换机挂在 L4 下）
                   HCI 超融合 / EDS 存储 / VDC+aDesk 桌面云 / EDR·aES·XDR·SIP 平台 /
                   业务服务器 / NVR / 存储交换机(万兆) / NAS备份
M  管理网络        带外管理（设备 eth0/MGMT 口，默认 10.251.251.251/24）
```

关键实例（附件一）：
- 印尼耐克：Internet → **AF-1000-FH2150B（出口）** → **AC-1000-B1500（网桥串接）** → 核心 C9407R×2（堆叠）
  → **aTrust-1000-B1030M 旁挂核心**；核心 → **数据中心防火墙 AF-1000-FH2300B** → 超融合/EDS 万兆汇聚；
  桌面云汇聚（RS6300）→ VDS-B-7950 桌面云；办公区终端/AP → 接入 → 核心。
- 实优特-越南：AF(ETH2 接光猫拨号，路由模式做网关 192.168.10.241) → AC(ETH1/ETH0 网桥，
  桥地址 192.168.10.242) → 核心交换机(10/20/30.254 三 VLAN 网关) → 汇聚(trunk G1/0/23-26)。
- 东阳光集团：公网出口 FW→WAF→核心；**分支接入区：广域网→WOC→FW**；核心→STA(旁挂)→华为云；
  业务区：XDR+EDR+SIP+业务服务器；服务器区另有 SDPC 控制中心 + Proxy 代理网关（零信任）。
- 金田纸业：运营商出口 → AF-1000-FH2100B → AC-1000-SK1300-HX → 核心；超融合服务器区
  （aServerDCS-W-100 蜂鸟一体机×2 + aServer-J-100Z 仲裁盒，4 千兆电口聚合）。
- 某总部多线路（第31页）：光联路由设备 → 三层交换机 → **AC(网桥部署·虚拟网线区域)** → **AF**
  → 左「透明部署区域」接分厂接入区(MPLS VPN 各分厂)，右「路由部署区域」接香港/联通/电信×3 出口线路
  ——即一台 AF 上同时存在透明接口组与路由接口组（混合模式实战）。

## 二、通用部署形态词汇表（工程师输入的触发词 → 链路形态）

| 形态 | 定义 | 触发词示例 | 功能/代价 |
|---|---|---|---|
| 路由模式 | 全部业务口为三层路由口，配 IP，按路由表/ARP 转发 | 出口、网关、路由、拨号、NAT、DHCP | 功能最全；对现网改动最大（改网关/路由） |
| 透明模式（网桥） | 二层网桥，access/trunk 口，按 MAC 表转发 | 串接、串联、网桥、透明、bridge | 不改 IP/路由即插即用；VLAN 环境需配 VLAN；支持多对一/一对多 |
| 虚拟网线 | 业务口成对直通转发（配对转发），不查 MAC/路由 | 虚拟网线、virtual wire | 性能最高、支持协议最广；只能带外管理 |
| 混合模式 | 部分口路由 + 部分口透明 | 混合、DMZ 公网 IP、部分透明 | 灵活；配置复杂（AF 全安全功能可用） |
| 旁路镜像 | 交换机镜像口/TAP 收包监听，不在主路径 | 旁挂、旁路、镜像、监听、审计 | 零风险不改变流量；仅检测审计类功能 + TCP RST 阻断 |
| 旁路引流 | 核心交换机策略路由(PBR)把流量引到设备再回注 | 旁路+认证、引流、重定向 | 可认证/管控；依赖交换机 PBR，配错会卡顿 |
| 单臂 | 一个接口旁挂三层设备，靠策略路由/回程路由工作 | 单臂、one arm | 不改拓扑；需对端引流配合 |
| 网关串联 | 设备当路由器/简单防火墙直接串在链路上当网关 | 网关模式、串联 | 功能完整；改动大 |
| 二级网关 | 串在出口防火墙之后的内层网关 | 二级网关、内层路由 | aTrust 这类无 NAT 设备的串联形态 |
| DSR 三角传输 | 请求经设备、响应直达客户端（服务器 loopback 绑 VIP） | 三角传输、真实源 IP、DSR | AD 服务器负载常用；性能好、服务器可见真实源 IP |

高可用（双机）词汇（附件二 + 工程师口述约定 + 深信服官方术语规范）：

> **术语规范（深信服官方叫法，工程师口语 → 规范说法）**
> - 功能模块官方入口：【系统】→【高可用性】（HA）。
> - 口语「双机」→ 官方规范叫 **双机热备**（两台设备：一台工作一台热备，经心跳口检测对端并同步配置/会话，故障触发主备切换）。运行模式官方叫法：**主备备份**、**主主负载**、**镜像模式**（AF）。
> - 口语「集群」→ 官方规范叫 **高可用集群**（AD 产品线官方用此名；两台以上，最少两台。AD 用「高可用性集群实现链路负载双主」）。
> - 三层组网下两台联动转发还有 **双机聚合**（AF：【系统】-【高可用性】-【双机聚合】，三层环境需勾选 HA-traffic）。
> - **双机只有两台；集群可以两台以上**——部署规划里声明几台就按几台建模；
>   只声明一台却要做双机/集群时，系统弹框提示补足（「双机高可用需要两台设备！」「集群至少需要两台设备！」）。

| 词汇 | 含义 |
|---|---|
| **双机（=HA 双机热备）** | 特指**两台**设备的高可用组：并排部署（一般在出口），两台之间互联**两条心跳线**（心跳线×2 聚合，如 eth5/eth6），再分别接上联（运营商线路，交叉布线）和下联（内网），主备（VRRP）或主主协同 |
| **集群** | 双机的泛化：**可以两台以上**（3 台及以上即集群），布线形态同双机——成员并排、成员间心跳互联（相邻成员双心跳）、上下联各成员独立出线；一般也部署在出口 |
| 集群 vs 双机的区别 | **双机只有两台，集群可以有两台以上**；两台时说"双机"或"集群"均可 |
| 主备模式（VRRP） | 一主一备，1 对 VRRP 组，虚 IP 对外；心跳线检测 |
| 透明双主（无 VRRP） | 两台透明口同时转发，仅做配置同步，不做主备切换（AF） |
| 主主模式 | 两台同时工作（AC 网桥主主：初始 AC-1 为主，桥地址互通即心跳） |
| 主心跳线/备心跳线 | AD：eth5 主心跳；eth6 备心跳仅 AD7.0.3 支持，建议空闲口 |
| 心跳聚合 | AF：心跳线×2 聚合（聚合口主备方式） |
| 交换网口 | AD 主备时备机经主机的交换网口转发（方案五"变相交叉"的关键） |
| bypass 对 | AF 硬件旁路对（eth0+eth1、eth2+eth3…）；业务口必须避开，防止关机成环 |
| 堆叠/VRRP 交换机 | 双核心交换机互联形态，是"SW 交叉型"方案的前提 |

> **透明部署的准确语义**（工程师确认）：透明（网桥）= 设备**接在网关和内网之间，充当交换机**
> （二层透传，不改 IP/路由）；出口部署 = 设备在互联网与内网之间做出口（路由模式当网关）。
> 本产品「部署规划」已按上述约定建模：备注写「集群/双机/热备」→ 两台（或 N 台）**并排节点 +
> 双心跳线 + 交叉上下联**；「透明」→ 网关与内网之间串接；「出口」→ 互联网与网关之间。

## 三、多产品组合双机标准链路（附件二官方最佳实践）

### 3.1 标准链路顺序

```
电信 ─接入交换机(分线)─┐                     ┌─接入交换机─ 联通
                      ├─ AD(路由,主备) ─ AF(透明/路由,主备) ─ AC(网桥主主/路由主备) ─ 核心交换机(堆叠/VRRP) ─ 内网
```

- **AD+AF**（无特殊要求）：AD 路由 + AF 透明 → 方案一（口字型）；备选方案二（全交叉型）
- **AD+AF**（AF 混合部署）：AD 路由 + AF 路由 → 方案三（半交叉型）；备选方案四（全交叉型）
- **AD+AF**（AF 带 IPSec VPN）：AD 路由 + AF 路由 → 方案五（变相交叉型）；备选方案六（SW 交叉型）
- **AF+AC**（无特殊）：AF 路由 + AC 网桥 → 方案七（口字型）
- **AF+AC**（AC 要做准入）：AF 路由 + AC 网桥（需定制包）→ 方案七；或 AF 路由 + AC 路由 → 方案八（SW 交叉型）
- **AD+AF+AC**（无特殊）：AD 路由 + AF 透明 + AC 网桥 → 方案九（口字型）；备选方案十（全交叉型）
- **AD+AF+AC**（AF 混合）：AD 路由 + AF 路由 + AC 网桥 → 方案十一（半交叉）；备选方案十二（全交叉）
- **AD+AF+AC**（AF 带 IPSec VPN）：AD 路由 + AF 路由 + AC 网桥 → 方案十三（变相交叉型）

### 3.2 五种布线形状（双机连线拓扑）

| 形状 | 布线 | 适用 |
|---|---|---|
| 口字型 | 各连各的：电信→AD-1→AF-1→核心-1，联通→AD-2→AF-2→核心-2，组成"口"字 | 最简推荐 |
| 全交叉型 | 上下层全交叉互联（AD-1↔AF-1/AF-2，AF-1/2↔核心-1/2） | 任意单点故障可绕行 |
| 半交叉型 | 部分交叉（AD 层各连各的，AF 层与核心交叉） | AF 路由模式 |
| 变相交叉型 | 利用 AD 备机"交换网口"功能，AF 主→过 AD 备→到 AD 主走流量 | AF 带 IPSec VPN 且无额外交换机 |
| SW 交叉型 | AD 与 AF（或 AF 与 AC）之间穿插 2 台堆叠交换机级联 | 客户有 2 台性能足够的交换机 |

### 3.3 双机配置要点（附件二原文归纳）

- AD：路由部署、主备模式；心跳主 eth5 + 备 eth6（7.0.3 起）+ 心跳口故障检测（选业务口如 eth2）。
- AF：
  - 透明 + 无 VRRP 组双主 = 不配双机热备，仅配置同步（方案一/九，AF/AC 均不切换，只有 AD 切换）；
  - 透明 + 1 对 VRRP 组（方案二/十）；路由 + 1 对 VRRP 组主备（方案三/四/七/八/十一/十二/十三）；
  - 心跳线×2 聚合；**业务口避开 bypass 对（eth0+eth1、eth2+eth3 是成对 bypass，防关机环路）**。
- AC：单网桥主主（桥地址互通即心跳，网桥不支持准入，要准入需打定制包找产品专家）；
  双网桥主主（方案十/十二）；路由主备（空闲口做心跳，如 eth1；**备机不能管理**，只能切主机管理或拆线单独管）。
- 链路探测：AC 与 AF 都允许 ping；AF 网口监测外网+内网业务口。
  注意：两外网口单独监控时，若运营商分线交换机断电会导致两台 AF 均判故障（附件二方案七注意）。
- AD 集群双主、AF VRRP 双主环境官方未给出，需单独与总部沟通（截止 AD7.0.3&AF7.4&AC11.9R1）。

## 四、逐设备部署方式库（15 种设备 × 各自多种方式）

> 每个设备给出：产品定位 → 部署方式表（位置 / 连线 / 功能 / 适用 / 双机 / 注意）→ 默认推荐 →
> 拓扑建模语义（在拓扑上落在哪两个节点之间或哪个节点的旁挂点）。

### 4.1 AF 下一代防火墙（inline · 出口/边界）

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 路由模式 | 出口位：光猫/运营商 ↔ 核心（AF 当网关） | WAN 口接运营商（多线多 WAN），LAN 口下联核心 | 全部功能（NAT/DHCP/VPN/策略） | 主备（1 对 VRRP），心跳×2 聚合 | 需改内网网关或路由；多线交叉布线参考方案三/四 |
| 透明模式 | 串接位：出口路由器下方 ↔ 核心 | 业务口成对（access/trunk），配 VLAN | 全部安全功能（无 NAT/VPN） | 透明双主（仅配置同步）或 1 对 VRRP | 不改 IP/路由；业务口避开 bypass 对 |
| 虚拟网线 | 同上（串接位） | 口对口直通 | 全部安全功能，转发性能最高 | 同透明 | 只能带外管理；需配对转发 |
| 混合模式 | 出口位 + 服务器区口（DMZ 透明接公网 IP 服务器） | 路由口组 + 透明口组并存 | 全部功能 | 主备 | 实例：一台 AF 左透明接分厂 MPLS、右路由接多 ISP 出口 |
| 旁路模式 | 旁挂位：核心/出口交换机镜像口 | 单镜像口（或加管理口） | 仅 WAF/IPS/APT/PVS/DLP/防篡改/流量审计 + RESET 阻断；应用控制不生效 | — | 零风险先观察，割接前常用 |
| 单臂模式 | 旁挂位：交换机一个路由口 | 单口 + 对端策略路由引流 | 路由类功能可用 | 主备 | 需三层设备 PBR 引流 |
| 数据中心防火墙角色 | 服务器区位：核心 ↔ 服务器区汇聚之间 | 串接（路由或透明） | 服务器区边界防护 | 主备/双主 | 实例：AF-1000-FH2300B 挂核心与超融合汇聚之间 |

默认推荐：**出口位，路由模式（无特殊）或透明串接（不改网）**。
建模语义：`出口 → AF → 核心`（路由=AF 是网关节点，透明=串在出口路由器与核心之间）；注明"数据中心/服务器区"时挂核心与服务器区之间。

### 4.2 AC 上网行为管理（行为管理）

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 网桥模式（首选） | 串接位：AF/路由器下方 ↔ 核心（外网层与内网层之间） | ETH1/ETH0 成对网桥 + 桥地址做管理 | 认证/审计/流控（无 NAT/V**/DHCP） | 单网桥主主、双网桥主主（桥地址互通=心跳） | 上架瞬间断网；**网桥不支持准入，需准入打定制包** |
| 网桥·虚拟网线转发 | 同上 | 口对口直通 | 同上，转发效率更高 | 同上 | 大流量场景用 |
| 路由模式 | 出口/二级网关位 | WAN+LAN，或单臂 | 全功能（NAT/DHCP/V**/认证/审计/流控） | 路由主备（空闲口心跳） | **备机不能管理**；需改网关 |
| 旁路镜像 | 旁挂位：核心交换机镜像口 | 镜像口（+eth0 管理） | 仅审计 + IP/端口控制 + TCP RST 阻断；**无认证、流控效果受限** | — | 零改动；需交换机配镜像 |
| 旁路引流（重定向认证） | 旁挂位：核心 + 核心上配 PBR | 监听/业务口 + 核心策略路由 | 旁路方式下可认证 | — | 引流策略配重复会卡顿 |

默认推荐：**网桥串接（内网已有网关时）**。
建模语义：`出口设备 → AC → 核心`（串接）；`核心 --旁挂--> AC`（镜像/引流）。

### 4.3 AD 应用交付（负载均衡）

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 路由模式 | 出口位（多线路接入交换机之后，最外侧）：分线交换机 ↔ AF/核心 | eth1/eth2 接多线，eth3(或 eth3&eth4 交换网口聚合) 下联 | 链路负载（出站选路 + 智能 DNS 入站）+ 服务器负载 | 主备：主心跳 eth5 + 备心跳 eth6(7.0.3) + 心跳口故障检测 | 官方组合链路中 AD 在最外侧；集群双主需与总部沟通 |
| 旁路模式（单臂） | 旁挂位：核心/交换机，WAN 口接入 | WAN 口（单臂需 WAN 口授权） | 服务器负载 + DSR 三角传输（服务器 loopback 绑 VIP，响应直达客户端、真实源 IP） | 主备 | 需回程路由/PBR 引流；与服务器同网段或路由可达 |

默认推荐：**多线路客户：出口位路由模式（AD→AF→AC→核心）**；**仅服务器发布：服务器区前旁路 DSR**。
建模语义：`多线分线交换机 → AD → (AF)` 或 `核心 --旁挂--> AD`。

### 4.4 SSL VPN（远程接入）

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 单臂模式（最常用） | 旁挂位：内网交换机（防火墙/路由器之后） | 一个 LAN 口接交换机；出口设备 DNAT/端口映射引流 | SSL VPN 远程接入、MFA | 主备/集群 | **内网业务服务器要加回程路由指向 VPN 设备**，否则隧道通业务不通 |
| 网关模式 | 串联位：直接接公网当路由器/简单防火墙 | 内网口+外网口（多线可多 WAN） | VPN + 基本路由/NAT | 主备 | 改动大，少用 |

默认推荐：**单臂旁挂出口区**。
建模语义：`核心/出口交换机 --旁挂--> SSL VPN`（公网入口由出口设备映射发布）。

### 4.5 aTrust 零信任（SDPC 控制中心 + Proxy 代理网关）

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 单臂旁挂（主流） | 旁挂位：核心交换机 | 1 个业务口 + 独立管理口 | 零信任接入（身份/终端可信认证后连接） | 单节点/本地集群/分布式集群 | 出口防火墙把接入端口（443/4430/44300）映射到公网；多线路要在控制中心登记全部公网映射地址；代理网关需可达资源服务器 |
| 二级网关串联 | 串联位：出口防火墙之后 | 内外两口 | 只有路由转发，**无 NAT** | 同上 | 不能做一级出口网关 |

组件分离部署（东阳光实例）：SDPC 控制中心放服务器区，Proxy 代理网关放出口/核心区，内外网认证访问方向分开画。
默认推荐：**旁挂核心 + 出口 NAT 映射发布**。
建模语义：`核心 --旁挂--> aTrust`。

### 4.6 WOC 广域网优化

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 两端成对串接 | 总部/数据中心出口一台 + 各分支出口一台（串在广域网链路两端） | 路由或透明串接 | 流削减/压缩/缓存/协议加速（削减 70% 冗余、丢包降至 1%） | 成对协同 | 加速类优化必须串接才生效 |
| 旁路 | 旁挂监测 | 镜像口 | 仅监测分析 | — | 不能优化 |

默认推荐：**广域网两端成对串接**。
建模语义：`分支广域网云 → WOC → 分支出口设备`（总部侧同理），两台 WOC 之间为加速隧道。

### 4.7 VDC 虚拟桌面管理 / 4.8 aDesk 桌面云

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 服务器区部署（唯一形态） | 服务器区：桌面云汇聚交换机（万兆）之下；VDS 一体机内置 VMP(虚拟化)+VDC(管控)+VS(存储) | 业务/管理千兆 + 存储/迁移万兆；LACP/静态聚合 | 云桌面交付、集中管控、数据不落地 | VDC/VS 主备、集群 | 云终端经内网接 VDC 认证取桌面；VMP/VDC 地址冲突影响全部终端 |

建模语义：`核心 → 桌面云汇聚交换机 → VDC/aDesk 集群`，云终端从 L6 接入。
触发词：桌面云、云终端、VDI、云课堂。

### 4.9 HCI 超融合

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 服务器区集群（≥3 台常见，2 台+仲裁盒亦可） | 服务器区：业务/存储汇聚（万兆）之下 | 每台：管理网 2 电口聚合 + 业务/VXLAN 复用 2 电口聚合 + 存储网 2 万兆光口；交换机堆叠（40G）；NAS 备份网络分离 | 计算/存储/网络一体，承载虚机与云桌面 | 分布式（aServer 一体机 + aServer-J-100Z 仲裁盒） | 存储网络必须万兆独立；管理/业务/存储三网分离是标准做法 |

建模语义：`核心 → 数据中心防火墙(可选) → 超融合汇聚交换机 → HCI 集群` + `存储交换机`。
触发词：超融合、私有云、aServer、一体机。

### 4.10 EDS 企业级分布式存储

部署方式：服务器区/存储网集群（唯一形态）。`超融合和 EDS 汇聚(万兆) → aStor-EDS 节点×N`，
万兆 LACP 聚合，为业务与备份提供存储池。触发词：分布式存储、aStor、存储池。

### 4.11 aES 统一端点安全 / 4.12 NGES 下一代端点安全（原 EDR 产品线）

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 管理平台旁挂 + 全网 agent（唯一形态） | 服务器区/办公网可达位置（MGR 平台，虚拟机或硬件） | 单管理口，与全网终端三层可达（agent 走 443） | 防病毒/EDR/补丁/外设管控/微隔离 | 平台主备/集群 | agent 推广方式：安装包/网页推广/联动 AC 推广/域推/脚本批量/虚机模板/离线包；平台只要求"可达"不要求在流量路径上 |

建模语义：`核心/服务器区 --旁挂--> aES/NGES 平台`，agent 覆盖 L6 终端与服务器（拓扑可画覆盖虚线）。
触发词：终端安全、防病毒、EDR、准入管控。

### 4.13 XDR 可扩展检测与响应

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 平台 + 探针组合（标准形态） | 平台在服务器区（SaaS/分布式 QCOW2/虚拟机）；潜伏威胁探针 STA 旁路镜像部署在外网口、核心、服务器区等关键节点交换机 | STA 镜像口收包（收包模式 AF_PACKET，镜像口可配 IP 用于通信） | 全流量采集检测 + 端点数据聚合，联动 EDR/aES/AF/SIP 自动回溯攻击链 | 平台集群 | 探针旁路不串接；镜像口带宽要按流量规划 |

建模语义：`服务器区 --旁挂--> XDR 平台`；`关键交换机 --镜像--> STA 探针 --> XDR`。
触发词：XDR、检测响应、探针、联动处置。

### 4.14 SDW-R（SD-WAN 安全路由）

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 出口 CPE 串接（替代出口路由器） | 每个站点（总部/分支）出口位，多 WAN 接运营商 | 多线路 WAN + LAN 下联 | 安全路由、BEST 智能选路、SD-WAN 组网（总部-分支隧道）、应用识别分流 | 双机/云端管控 | 分支支持 0 接触分钟级上线；可订阅 SASE 云端安全 |

建模语义：`互联网 → SDW-R → 内网`（每站点一台，站点间 SD-WAN 隧道）。
触发词：SD-WAN、组网、分支、智能选路、替代路由器。

### 4.15 XAC（云原生安全平台 ≈ 云安全资源池 CSSP）

> 深信服公开产品线中无"XAC"命名，能力对应**云安全资源池 CSSP**（安全能力服务化、按需交付）。

| 部署方式 | 位置 | 连线 | 功能 | 双机 | 注意 |
|---|---|---|---|---|---|
| 旁挂交付 | 云平台/服务器区（云管理网） | 管理口对接云管平台 | 防火墙/WAF/IPS 等安全能力以服务形式按需编排给租户/业务 | 集群 | 解耦合/紧耦合两种部署模式；CSSP 4.0.10 起默认限制登录超融合平台 |

建模语义：`服务器区/云管理网 --旁挂--> XAC`。
触发词：云安全、资源池、安全服务化。

## 五、与当前 CyberNWT「部署规划」建模的差距与落地建议

现状（server.py `SANGFOR_DEVICES` + `build_real_network`）：每设备只有单一默认 `mode`
（inline/onearm/serverzone 三值）+ 工程师备注关键词（出口/串接/旁挂）映射到 up/down/bypass 三种位置。

按本知识库，建议演进：

1. **每设备多方案枚举**：`SANGFOR_DEVICES[key]['modes'] = [{mode, pos, wiring, note}, ...]`，
   按 4.x 表录入；工程师备注命中触发词即选中对应方案，未命中取 `default`。
2. **位置语义细化**（up/down/bypass 不够用）：
   - `up`（出口链）内再排序：**AD → AF → AC(inline 时) → 出口路由器**（附件二标准链路，AD 在最外侧）；
   - 新增 `serverfront`（服务器区前串接：数据中心防火墙 AF、AD 服务器负载）；
   - 新增 `wanpair`（WOC/SD-WAN 两端成对，拓扑上画分支广域网侧）；
   - `bypass` 细分 `mirror`（镜像纯审计）与 `pbr`（引流可认证）；
   - `serverzone` 设备按实测发现的服务器/管理网段挂接（有实测服务器网段时挂该网段侧，否则挂核心）。
3. **HA 建模**：工程师输入"双机/主备/热备/集群"时，同设备建模两台节点 + 心跳虚线，
   建议文案按附件二给布线形状（口字型/全交叉/半交叉/变相交叉/SW 交叉）与心跳口规划。
4. **AF 角色区分**：默认"出口防火墙"；备注含"数据中心/服务器区"时建模到 `serverfront`。
5. **约束提示进建议**：AF 业务口避开 bypass 对（eth0+eth1/eth2+eth3）；AC 网桥做准入需定制包
   （否则转 AC 路由 + SW 交叉方案八）；AD 备心跳口仅 7.0.3+；AC 路由主备备机不可管理；
   单臂/旁路引流方案提醒内网服务器加回程路由。
6. **组合推荐**：录入附件二 3.1 的组合→方案映射表，工程师同时选多台设备时给出官方推荐组合
   （如 AF+AC 无特殊 → AF 路由 + AC 网桥，口字型）。
